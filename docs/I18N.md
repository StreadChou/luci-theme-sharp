# 多语言

[文档目录](README.md) · [项目首页](../README.md)

Sharp 使用 LuCI 标准的 gettext PO / LMO 机制，跟随 LuCI 当前语言。英文是代码中的原文，也是缺少翻译时的回退文本；简体中文随主题安装，不需要另装 Sharp 语言包。目前不在 Sharp 设置页添加语言选择器。

项目自己的登录页、菜单、搜索、弹窗、提示及无障碍标签均已纳入翻译。LuCI 原生页面和其他插件继续使用各自的语言包；主题的中文语言目录不会替代它们。

- [`po/languages.json`](../po/languages.json)：注册语言。英文使用 `source: true`，中文 `zh_Hans` 对应 LuCI 的 `zh-cn`。
- [`po/zh_Hans/sharp.po`](../po/zh_Hans/sharp.po)：中文翻译。
- [`po/templates/sharp.pot`](../po/templates/sharp.pot)：从 TypeScript、`.ut` 模板和菜单 JSON 自动提取的英文条目。
- [`frontend/ts/i18n.ts`](../frontend/ts/i18n.ts)：`t('English message')` 用于普通文字，`tn(count, '%d result', '%d results')` 用于数量及复数。数量应放在完整句子里，不拼接翻译片段。

## 文案与翻译上下文

新增 TypeScript 文案使用 `t('English message')`；数量文案使用 `tn(count, 'singular', 'plural')`，提供完整句子，不拼接语言片段。新增主题文案时同时补充简体中文翻译，包含提示、空状态和无障碍标签。

主题文字使用 `sharp` 翻译上下文，避免覆盖 LuCI 原生页面的通用词条。TypeScript 的接口自动传入该上下文，`.ut` 模板使用 `_('English message', 'sharp')`。翻译文件中请保留 `msgctxt "sharp"`。菜单 JSON 不支持上下文，因此项目独有的 `Sharp theme settings` 菜单标题保留为普通词条。

## 新增语言

以下命令在项目根目录执行，以日文为例：

1. 运行 `npm run i18n` 更新模板，创建 `po/ja/` 目录，将 `po/templates/sharp.pot` 复制为 `po/ja/sharp.po`，填写译文和正确的 `Language`、`Plural-Forms` 文件头。
2. 在 `po/languages.json` 增加 `"ja": { "name": "日本語 (Japanese)", "locale": "ja" }`。
3. 运行 `npm run check`。开发容器已运行时，再执行 `npm run dev:sync`；持续运行 `npm run dev` 时会自动同步。

## 构建产物

构建会生成 `sharp.<locale>.lmo` 和语言注册脚本，均随主题源码分发。不要手工修改这些生成文件。所有已注册的 Sharp 翻译都打包进主题，不会生成拥有重复文件的独立 `luci-i18n-sharp-*` 包。构建工具使用随项目附带的 OpenWrt `po2lmo` 源码，首次编译后缓存到 `.dev/tools/`，之后不需要联网下载工具。

维护翻译工具时，保留 [po2lmo 来源与修改说明](../scripts/vendor/po2lmo/README.md)及其 [Apache-2.0 许可证](../scripts/vendor/po2lmo/LICENSE)。
